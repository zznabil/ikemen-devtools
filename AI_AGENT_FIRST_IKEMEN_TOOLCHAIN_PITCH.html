AI-Agent-First Ikemen Toolchain

Make MUGEN code understandable.

A semantic development toolchain for MUGEN and Ikemen GO: find broken state transitions, missing assets, dead AI routes, and unsafe edits before they become runtime surprises.

Built as a Go CLI and reusable semantic library

The problem

MUGEN files look like simple configuration, but they behave like a programming language spread across many files and dialects.

  • A ChangeState target may not exist.
  • A character definition may reference missing CNS, CMD, or ST files.
  • AI routes can be silently disabled with Null;ChangeState.
  • Dynamic expressions can hide unreachable or ambiguous behavior.
  • Generic IDEs cannot understand the relationship between states, commands, helpers, and assets.

Real example

The tool found that downloaded Gogeta AI referenced transformation states that did not exist:

808   SS5 ground
809   SS5 air
813   SSB air
814   SSBE ground
815   SSBE air

That is exactly the kind of defect ordinary text search misses.

What it is

CLI

ikm check diagnoses a character workspace. ikm index exports a deterministic SQLite-compatible index.

Semantic library

Go packages parse documents, resolve references, load DEF workspaces, classify dynamic targets, and emit diagnostics.

TDD foundation

Every package has focused tests for malformed input, duplicate definitions, missing files, resolution, output, and stable ordering.

Future adapters

The core can later power MCP, LSP, Tree-sitter, Serena, Semble, or code-graph integrations without changing semantic truth.

Architecture

1. Source files
DEF · CNS · ST · CMD · AIR · SFF · SND
2. Tolerant parser
Preserves source spans, duplicates, comments, and recoverable malformed input.
3. Semantic IR
Documents, symbols, references, diagnostics, and resolution classifications.
4. Workspace resolver
Follows DEF file references with deterministic path resolution and missing-file reporting.
5. Agent interfaces
CLI today; MCP, LSP, retrieval, and review-graph adapters next.
Ikemen files
     ↓
Parser → Semantic IR → Resolver → Diagnostics
                                  ↘ SQLite / FTS5 index
                                  ↘ CLI / MCP / LSP adapters

What it catches today

State integrity

Undefined numeric ChangeState and SelfState targets, duplicate same-file states, and dynamic references.

AI integrity

Compound command references, disabled AI transitions, ambiguous targets, and state routes that do not resolve.

Workspace integrity

Missing CMD, CNS, ST, numbered ST, and common-state files; duplicate source loading; Windows path handling.

Data safety

Stable diagnostics, SQL escaping, collision-safe IDs, refresh-safe index export, and safe output-file writes.

Try it

Location:

<path-to>/ikemen-devtools
cd "<path-to>/ikemen-devtools"

go run ./cmd/ikm check path\to\character.def
go run ./cmd/ikm check --json path\to\character.def
go run ./cmd/ikm index path\to\character.def > index.sql

Current verification: gofmt, go test ./..., and go vet ./... pass.

Why this foundation

Ikemen semantics first

The engine’s behavior is the source of truth. Search and retrieval never replace semantic resolution.

Replaceable interfaces

Serena, Semble, codegraph, and MCP can attach later as adapters instead of becoming hard dependencies.

Small vertical slices

Start with states, commands, and DEF file loading. Add AIR, assets, motif fallback, and runtime tracing incrementally.

Roadmap

Next

  • Finish exact Ikemen expression evaluation.
  • Add common/motif fallback resolution.
  • Parse AIR and validate referenced animations.
  • Index helper IDs, variables, palettes, and assets.

Then

  • Expose semantic queries through MCP.
  • Add LSP navigation and diagnostics.
  • Connect Semble or code-review-graph as retrieval adapters.
  • Add runtime tracing for AI decisions and state transitions.

The pitch

MUGEN development does not need another text editor. It needs a semantic layer that understands what the engine actually loads and executes.

Ikemen Devtools turns scattered character files into a navigable, testable, agent-readable system—starting with a boring, reliable CLI and growing toward MCP, LSP, retrieval, and runtime intelligence.
